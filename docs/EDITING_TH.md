# คู่มือแก้ไข JUBUTSU

## 1. โครงสร้าง

```text
project.godot
scenes/
  main.tscn               ประกอบระบบทั้งหมด
  school_level.tscn       ฉากจริงที่เปิดและจัดวัตถุใน Godot ได้
  player.tscn             ตัวผู้เล่น กล้อง และไฟฉาย
scripts/
  game.gd                เริ่มเกม/พักเกม/เปลี่ยนรอบ/จบเกม/ปฏิสัมพันธ์
  run_rules.gd           ตัดสินการผ่านรอบ แยกจากภาพและเสียง
  anomaly_director.gd    เลือกเหตุการณ์ คืนค่าวัตถุ และเล่นเอฟเฟกต์
  school_level.gd        วัสดุโมเดล แสง และกระจกสะท้อน
  actor_visual.gd        เปลี่ยนโมเดลและ animation ตัวละคร
  player.gd             เดิน มอง วิ่ง
  hud.gd                เมนูและข้อความภาษาไทย
  audio_manager.gd      เสียงรอบตัวและเสียงเมนู
  game_config.gd        นิยามค่าที่แสดงใน Inspector
data/
  game_config.tres       ค่าปรับสมดุล
  anomalies.json        รายการความผิดปกติ 27 แบบ
assets/
  models/school.glb      ไฟล์ที่ผู้ใช้ส่งมา
  audio/*.wav           เสียงชั่วคราวที่สร้างขึ้นสำหรับเกมนี้
tools/
  test_game.gd          ตรวจระบบอัตโนมัติ
  capture.gd            เรนเดอร์ภาพหน้าจอสำหรับตรวจงาน
  build_level.gd        ตัวช่วยสร้างฉากเริ่มต้น (ไม่จำเป็นต่อการเล่น)
```

## 2. ปรับเกมโดยไม่แก้โค้ด

คลิก `data/game_config.tres` ใน FileSystem แล้วแก้ค่าใน Inspector:

- `Anomaly Chance`: โอกาสเกิดเหตุการณ์ในรอบที่มีสิทธิ์ ค่าเริ่มต้น 0.65
- `Bell Rooms`: ห้องที่ต้องกดกระดิ่งหนึ่งครั้ง
- `Walk Speed` / `Sprint Speed`: เมตรต่อวินาที
- `Eye Contact Seconds`: เวลามองตาต่อเนื่องก่อนแพ้
- `Chase Seconds`: ระยะหนีเริ่มต้น 3 วินาที ต้องสัมพันธ์กับความยาวทางเดิน; เพิ่มมากเกินไปอาจหนีไม่ทันก่อนถึงขอบฉาก
- `Chase Speed`: เร็วกว่าเดิน ช้ากว่าวิ่ง
- `First Room Safe`: บังคับห้อง 1 ให้ปกติ
- `Explain Failures`: ปิดเป็นค่าเริ่มต้น เปิดเฉพาะเมื่อต้องการดูสาเหตุที่เริ่มใหม่ระหว่างพัฒนา
- `Forced Anomaly`: -1 สุ่ม, 0 ปกติ, 1–27 บังคับเหตุการณ์ ห้องแรกปลอดภัยและห้องสุดท้ายยังมีลำดับความสำคัญสูงกว่า
- `Debug Enabled`: ปิดเป็นค่าเริ่มต้น เปิดเพื่อใช้ F3 ระหว่างพัฒนา

ค่า `Final Room` เริ่มต้นเป็น 13 ป้ายทางออก ข้อความบนกระดาษ และหน้าจอจบอ่านจากค่านี้ร่วมกัน
หน้าตั้งค่าแยกจากเมนูหลักและหน้าพัก ปรับเสียง ความไวเมาส์ และเต็มหน้าจอได้ บันทึกอัตโนมัติใน user://settings.cfg

## 3. ย้ายวัตถุ

เปิด `scenes/school_level.tscn` ในมุมมอง 3D แล้วขยาย `Props`:

- `Bell`, `Note`, `Posters`, `ExtraPosters`: กระดิ่ง กระดาษ และป้าย
- `Door`, `ClassroomInterior`, `Blackboard`: ประตูเลื่อน ห้องเรียนต้นแบบ และกระดาน
- `Speaker`, `Extinguisher`, `Sink`, `Bin`, `Hand`: วัตถุสังเกต
- `Mirror`: กรอบและพื้นผิวกระจก
- `Walker`, `Peeper`, `WindowWatcher`, `Pursuer`: คนเดิน คนแง้มประตู คนที่หน้าต่าง และผู้ไล่ตาม
- `RoomNumber`, `NextNumber`, `ExitSign`: ป้ายหมายเลขและป้ายหลอก

ปรับ Transform / Mesh / Material ของลูกได้ตามปกติ **คงชื่อ node หลักไว้** เพราะระบบใช้ชื่อนี้อ้างอิง
ระบบจำ transform, การมองเห็น, material และข้อความของวัตถุเมื่อเริ่มฉาก แล้วคืนค่าก่อนแต่ละรอบ จึงไม่ต้องเขียนการซ่อนกลับสำหรับวัตถุเดิมทุกครั้ง

`Spawn`, `ForwardExit`, `BackExit` เป็นจุดเกิดและทางเปลี่ยนรอบ ทางผ่านอยู่สุดทางเดิน ตรวจระยะสามแกน ปรับขนาดพื้นที่ตรวจได้ในกลุ่ม Route ของ SchoolLevel
`MapExpansion/SchoolArchitectureCollision` ใช้รูปชนจากสถาปัตยกรรมจริง มีรูปชนแยกสำหรับรั้วดาดฟ้าและห้องเรียน ดูรายละเอียดใน `docs/MAP_TH.md`
ถ้ายืดฉากหรือย้ายขอบ ให้ปรับ collision ด้วย เลือก node หลัก `SchoolLevel` แล้วปรับกลุ่ม `Event Positions` ใน Inspector เพื่อย้ายจุดเริ่มไล่ตาม ช่วงเดิน NPC จุดเปิดประตู และระยะเลื่อนบานประตู
กระจกปัจจุบันเป็นระนาบตั้งฉากแกน X: ย้ายตำแหน่งได้ แต่ถ้าหมุนหรือเปลี่ยนขนาด ต้องแก้ frustum ใน `school_level.gd`

GLB ต้นฉบับอยู่ใต้ `SchoolModel` และมีตำแหน่ง X=58.45 เพื่อเลื่อนทางเดินเข้าใกล้จุดกำเนิด
`school_level.gd` ซ่อนชิ้นประตูที่แทนด้วย Props/Door และประตูดาดฟ้าที่เปิดถาวร ผนังดาดฟ้าใช้ชิ้นตัดช่องใหม่ใต้ MapExpansion/CarvedWalls พร้อมแก้วัสดุเมื่อรัน ไม่ได้เขียนทับ GLB

## 4. เปลี่ยนตัวละคร

1. ใส่ GLB ใหม่ใน `assets/models/`
2. เปิดฉากโรงเรียน เลือก `Props/Walker`
3. ลากโมเดลไปใส่ `Normal Model` ใน Inspector
4. ใส่เวอร์ชัน `Faceless Model`, `Offering Model`, `Ghost Model` ตามต้องการ
5. ตั้ง `Model Scale` และ `Model Rotation Degrees` ให้เท้าอยู่พื้นและหันด้านหน้าไปทาง -Z
6. ถ้ามี AnimationPlayer ภายในโมเดล กรอกชื่อแอนิเมชันลง `Walk Animation` และตั้ง animation ให้ loop ใน import
7. เลือก `Pursuer` แล้วใส่โมเดลใน `Attacker Model`; ตั้งของ `Peeper` และ `WindowWatcher` แยกได้

ตัวละครใหม่จะอยู่ใต้ `ArtRoot` และซ่อนรูปทรงชั่วคราวให้อัตโนมัติ อย่าลบ `Head`, `LeftEye`, `RightEye` หรือ `Offer`: เป็นจุดอ้างอิงของระบบ
หากความสูงโมเดลไม่ตรง ให้ปรับตำแหน่ง Head anchor ด้วยเพื่อให้กฎสบตาตรงกับใบหน้า
ตัวสะท้อนในกระจกใช้โมเดลของ Walker; ให้ใส่ Ghost Model ที่ Walker สำหรับเหตุการณ์กระจก
ช่อง variant ที่ไม่ได้ใส่จะใช้ Normal Model แทน จึงควรส่งโมเดล variant มาด้วยหากต้องการความแตกต่างเมื่อเปลี่ยนงานภาพจริง
ระบบแอนิเมชันในรุ่นนี้เป็น adapter เบื้องต้น ยังต้องต่อท่ายื่นของ/วิ่ง/ต่อยจาก rig ที่ส่งมา

## 5. เพิ่มหรือปรับความผิดปกติ

ใน `data/anomalies.json`:

```json
{
  "id": 12,
  "title": "ไฟกระพริบเป็นจังหวะ",
  "effect": "flickering_lights",
  "enabled": true,
  "weight": 1,
  "min_room": 2,
  "art_status": "prototype"
}
```

`enabled=false` ตัดออกจากการสุ่ม, `weight` เพิ่มโอกาสเมื่อเทียบกับเหตุการณ์อื่น, `min_room` จำกัดห้องแรกที่เริ่มเกิด
`effect` และ `art_status` เป็นชื่ออ้างอิง/สถานะสำหรับอ่าน ส่วนการรันเอฟเฟกต์อ้างอิง `id`
การเพิ่มชนิดพฤติกรรมใหม่ต้องเพิ่มกรณีใน `reset_room()` และถ้าต้องอัปเดตทุกเฟรมให้เพิ่มใน `tick()` ของ `anomaly_director.gd`
เพิ่มค่าช่วง `forced_anomaly` ใน `game_config.gd` ถ้าจำนวนเกิน 27
เมื่อเพิ่ม node ขณะรัน ต้องจัดการลบทิ้งตอน reset เอง เพราะระบบ snapshot เก็บเฉพาะ node ที่มีตั้งแต่เริ่มเกม

## 6. เสียง

แทนที่ WAV ใน `assets/audio` โดยคงชื่อ bell, step, knock, water, fail, success และ hum แล้วรอ Godot import
ใช้ PCM WAV mono จะตรงกับต้นแบบ เสียง hum ตั้ง loop ในโค้ด ส่วนเสียงอื่นจบแล้วลบตัวเล่นเอง
ไฟล์ชั่วคราวสร้างด้วย `tools/make_audio.cjs` ไม่มีเสียงจากแหล่งภายนอก

## 7. ทดสอบก่อนส่งต่อ

- F5 ทดลองเล่นปกติและพยายามไปถึงห้อง 7
- เปิด Debug Enabled ก่อน แล้วกด F3 เลือกเหตุการณ์ทีละรายการ; โหมดนี้เริ่มห้อง 2 จึงยังต้องกดกระดิ่ง
- ทดสอบกรณีกดกระดิ่งสองครั้ง, มองตา, รับของ, เชื่อป้ายหลอก และวิ่งหนี
- รัน `tools/test_game.gd` เพื่อจับข้อผิดพลาดด้านกฎ/การคืนค่าฉาก

อย่ารัน `tools/build_level.gd` หลังจัดฉากเองโดยไม่สำรอง เพราะเครื่องมือนี้เขียนทับ `scenes/school_level.tscn`
การเล่นเกมปกติไม่เรียกตัวสร้างฉากหรือสร้างเสียงใหม่

## 8. เมื่อต้องการ Export ในอนาคต

เลือก Export Resources เป็นทุก resource และเพิ่ม `*.json,CREDITS.md` ในช่องตัวกรองไฟล์ที่ไม่ใช่ resource เพื่อให้รายการเหตุการณ์ติดไปในแพ็กเกจด้วย
ใส่ฟอนต์ไทยที่อนุญาตให้แจกจ่ายแทน SystemFont แล้วลองรันบนเครื่องที่ไม่มี Godot
ขั้นตอนนี้ยังไม่ได้ทำหรือทดสอบในรุ่นต้นแบบปัจจุบัน



## บรรยากาศและผนังปิดทาง

RouteBarriers มีผนังคอนกรีตและบัวผนังให้เห็นตรงปลายทางและด้านห้องเรียน ฝั่งหน้าต่างมีผนังเตี้ยกับกระจกปิด เพื่อยังสังเกตเหตุการณ์คนนอกหน้าต่างได้ รูปชนและจุดผ่านรอบอยู่ตำแหน่งเดิม

แก้ความสว่างแต่ละดวงใต้ Lights ได้โดยตรง ระบบเหตุการณ์คูณกับค่าที่จัดไว้แทนการเปลี่ยนทุกดวงให้เท่ากัน กลุ่ม Atmosphere ที่ SchoolLevel ปรับแสงพื้นฐานและความสว่างหลอดไฟได้ หมอกและสีท้องฟ้าแก้ใน WorldEnvironment

พื้นฐานฉากใช้ไฟสลับโทนเย็นกับเหลืองหม่น เงาและหมอกระยะไกล ไม่มีการสุ่มไฟกระพริบเพิ่มในรอบปกติ เพื่อให้เหตุการณ์ไฟกระพริบยังเป็นสิ่งที่ผู้เล่นจำแนกได้

## ป้ายในเกม — 5 ตุลาคม 2026

ลบป้ายตกแต่ง 11 จุด: ชื่อปีกอาคาร ป้าย RETURN, BELL, CLASS 2–B, คำกำกับกระจก, FIRE, WC และป้ายชื่อชั้น/ดาดฟ้า ซ่อนชื่อเกม เวลา และคำว่า ESC พักจาก HUD ขณะเล่น การควบคุมยังดูได้จากเมนู

คงเลขห้องปัจจุบันและห้องถัดไป ป้ายทางออกหลอก กระดาษกฎ โปสเตอร์ปกติ/ผิดปกติ และข้อความกระดาน เพราะเกี่ยวกับกฎหรือการสังเกตความผิดปกติ เมนูและหน้าตั้งค่ายังใช้งานได้ตามเดิม

ลบป้าย ROOFTOP/EXIT และเลขด่านถัดไปตามคำขอแล้ว เลขห้องปัจจุบันยังใช้บอกความคืบหน้า เดินถึงปลายทางเพื่อเปลี่ยนห้องได้เหมือนเดิม เหตุการณ์ 15 (เลขด่านถัดไปผิด) หยุดสุ่ม และเอากฎเกี่ยวกับป้าย EXIT ออกจากกระดาษเพราะไม่มีป้ายให้โต้ตอบแล้ว

## แสงตรงหลอดไฟ — 5 ตุลาคม 2026

Lights/Tube_Object* จำนวน 12 ดวงอ้างตำแหน่งกึ่งกลาง mesh หลอด Emissive ใน GLB จุดกำเนิดแสงอยู่ต่ำกว่าศูนย์กลางหลอด 4.5 ซม. เพื่อพ้นเนื้อหลอดและไม่เกิดเงาบังตัวเอง ไฟห้องเรียนอยู่ใต้ ClassroomLuminaire ทุกดวงมี metadata source_fixture บอกชิ้นส่วนที่เกี่ยวข้อง

แก้ความสว่าง/ระยะไฟใน Lights และค่าความสว่างผิวหลอด Tube Emission Per Power ที่ SchoolLevel ได้ ทั้งไฟและผิวหลอดตอบสนองต่อเหตุการณ์ไฟดับ/ไฟกระพริบพร้อมกัน หากย้ายหลอดในโมเดลต้องย้าย Light ที่คู่กันด้วย

## ทางเข้าและทางออกหมอก

EntranceMist และ ForwardMist ใช้ฉากร่วม scenes/exit_mist.tscn มีม่านหมอกเคลื่อนไหวหลายชั้น รองรับ Compatibility renderer วัสดุอยู่ใน shaders/exit_mist.gdshader ปรับสี mist_color และความหนา density ของแต่ละชั้นได้ ซ่อนภาพกำแพงและกรอบประตูเฉพาะปลายทาง แต่คงรูปชนกันหลุดไว้หลังจุดเปลี่ยนห้อง

ForwardExit/BackExit ยังเป็นจุดเปลี่ยนห้องเดิม หมอกไม่มีรูปชน จึงเดินผ่านได้ ใช้ tools/test_mist_passages.gd ตรวจการเดินผ่านทั้งสองด้าน

## UI สยองขวัญ — 6 ตุลาคม 2026

หน้าหลัก พักเกม กระดาษกฎ หน้าจบเกม และตั้งค่าใช้สีดำหม่น/ขาวซีด/แดงเข้มร่วมกัน มีพื้นหลังไล่เงาและเกรนเบา ๆ พร้อมเฟดเข้า 0.22 วินาที ปรับสีหลัก INK, PAPER, MUTED, ACCENT และขนาดตัวอักษร/ระยะขอบได้ใน scripts/hud.gd ฟังก์ชัน button() และ style_slider() คุมหน้าตาของปุ่มและแถบเลื่อนร่วมกันทั้งหมด

ข้อความไทยใช้ Leelawadee UI โดยมี Noto Sans Thai และ Tahoma สำรอง ชื่อภาษาอังกฤษใช้ Georgia พร้อม Times New Roman สำรอง ขณะเล่นยังคง HUD แบบน้อยชิ้นตามเดิม ทดสอบหน้า UI และการพัก/กลับเข้าเกมด้วย tools/test_menu.gd

### กระดาษโน้ต
หน้า note แยกจากเมนูหลักเป็นกระดาษเก่าตรงกลาง ขนาด 620×730 พร้อมรอยพับและขอบคล้ำจาก shader แบบภาพนิ่งใน build_note() ของ scripts/hud.gd ปรับขนาด สี และระยะขอบได้ในฟังก์ชันนี้ เนื้อหากฎยังมาจาก configure_rules() ตามค่าห้องกระดิ่งจริง กด E, ESC หรือปุ่มวางกระดาษเพื่ออ่านจบและเล่นต่อ
